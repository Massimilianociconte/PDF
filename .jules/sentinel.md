## 2024-02-14 - Pass-the-Hash / Timing Attack Vulnerability
**Vulnerability:** The authentication logic compared the password directly with the stored config (`password == settings.admin_password`) before attempting hash verification. This allowed an attacker who obtained the password hash to log in by using the hash itself as the password (Pass-the-Hash). It also exposed a timing attack vulnerability for plaintext configurations.
**Learning:** Supporting both plaintext and hashed configurations requires careful ordering of operations. Always verify against the strongest method (hash) first. If a fallback to plaintext is necessary (legacy/dev support), ensure it only happens when the stored secret is unequivocally NOT a hash, and use constant-time comparison (`secrets.compare_digest`).
**Prevention:** Avoid direct string comparison (`==`) for secrets. Use `verify_password` logic that handles format detection (hash vs plain) safely, or strictly enforce hashed storage to eliminate ambiguity.
